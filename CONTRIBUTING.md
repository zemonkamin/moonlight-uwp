# Contributing

This project targets Windows 10 Mobile with Visual Studio 2017, v141, and Windows SDK 15063. Changes must remain compatible with the minimum OS build 14393 and ARM32. Keep issues, pull requests, code comments, and public documentation in English.

## Set up and build

Clone with submodules, then run from the repository root:

```powershell
.\scripts\Bootstrap.ps1
.\scripts\Build.ps1 -Configuration Release -Platform ARM -Package
```

Use x86 or x64 for desktop development. Any CPU and ARM64 are not supported. See [README.md](README.md) for signing and optional desktop self-tests.

## Dependency changes

Use official upstream repositories. Record root revisions in `dependencies.lock.json` and the corresponding Git submodule entries. Include reproducible compatibility changes in `patches/`; Bootstrap must apply them to the pinned revision. Update [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) when dependencies change.

The native project is generated by `scripts/Generate-NativeProject.ps1`. Update the generator when changing its source lists or build settings.

## Submitting changes

Explain the behavior being changed and how it was verified. Include the configuration, architecture, SDK, and toolset used for build checks. Describe device tests separately from source review and compilation. For latency work, distinguish queue capacity, processing time, and measured end-to-end delay.

Keep changes focused and preserve H.264 reference-frame recovery, TLS certificate pinning, and persistent client identity. Test shutdown and reconnect behavior when changing queues or connection ownership.

Do not include local PFX files, client keys, host pairing data, IDE settings, build outputs, or packages in a source pull request. Use redacted logs in bug reports. Run `scripts/Clean.ps1` to remove generated files; note that it removes local keys under `build/signing/` as documented in the README.

## Preparing a GitHub fork

Publish the complete source tree, compatibility patches, dependency lock file, license notices, and Git submodule entries. Keep submodule URLs pointed at their official sources. A plain GitHub source ZIP is not a complete offline build bundle because it omits submodule contents.

Choose your own repository remote and release signing identity. Development certificates generated locally are not part of the source distribution. When publishing binaries, include the matching source revision and make the corresponding dependency sources available under their licenses.
